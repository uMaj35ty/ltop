# LAN 发现

LAN 盒回答"我网上有谁"——不要 root、不用 nmap、不出 TUI。发现靠两个机制:

1. **被动** —— 每次刷新都读内核邻居表（ARP/NDP），机器说 过话的设备立刻
   出现，带着内核还记着的新鲜度。
2. **主动 UDP knock 扫描** —— 后台线程遍历本地子网（由本机接口地址+前缀
   推出），向候选地址发小 UDP 包。包本身多半无人应答，但这个尝试会让内核
   去做 ARP 解析，于是*内核*会把邻居报出来——ltop 自己不需要 raw socket，
   也不需要 root。扫描节奏是 `sweep_interval_s`（默认 60 秒），安静的
   网络可以关掉（`sweep = false`）。主屏按 `s` 也能随时开关。

两路结果按（接口, IP）合并。主机名走尽力而为的三级解析——mDNS 反查 →
NetBIOS node status → 反向 DNS；网关有标记；macOS 的邻居表脱敏绕过方式是
经路由 socket 逐条探测内核缓存——那边哪些可见哪些不可见见
[兼容性 → macOS](compat.md#macos)。真实 MAC 来自 `ltop lan-setup`：一个
每用户 launchd 代理，经 Apple 平台签名工具轮转 `arp`/`ifconfig` 快照
（免 root、免 entitlement）——未启用时 MAC 显示 `—`。

## 每个邻居显示什么

| 列 | 含义 |
|---|---|
| IP / hostname | 地址，能解析就带 mDNS 名 |
| MAC | 硬件地址（macOS 未启用 `ltop lan-setup` 时显示 —） |
| iface | 从本机哪块网卡可达 |
| Σ conns | CONNS 里指向这个对端的活跃连接数 |
| rate | 到这个对端的当前 rx+tx |
| Σ bytes | ltop 启动以来到这个对端的累计字节 |

流量列是重点: LAN 盒和 CONNS 共用连接账本，每个邻居自带属于它的那一份
流量。

## 交互

- `e` 循环 LAN 排序（ip → hostname → mac → iface）。
- `↑↓` 选中；选中会*跟着邻居走*——重排、扫描后位置不丢（设备从 ARP 里短暂
  消失也不影响）。
- `enter` **置顶**邻居——钉在最上、红色高亮——同时**让 CONNS 只看这个
  对端**。这是"这台设备到底在干什么"的快车道: 选中、回车、读逐连接分解。
  再按 `enter` 取消；`esc`/`f` 也能清。
- `l` 单焦点 LAN 盒；`z` 全屏（子网设备多的时候好用）。

## 刻意不做的

- 子网从本机接口推出，不扫描已连接前缀之外的地址。
- 完全屏蔽 ARP 的设备（个别开了防火墙的主机）只有在内核因其他流量留下
  缓存时才出现。
- 扫描只是"发往空处的 UDP": 不做 TCP connect、不探端口、不发 raw 包——
  在操作系统眼里就是几次普通的（失败的）投递尝试。
