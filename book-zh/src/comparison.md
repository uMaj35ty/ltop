# 与其他工具对比

ltop 不想取代 btop 或 nethogs。它补的是它们空着的那一块: 这台机器、这个
局域网上谁在和谁通信——按进程、按连接，且带机器可读的数据面。

## btop —— 建议两个一起用

系统总览归 btop: CPU、内存、传感器、全部进程。ltop 借了它的视觉语言
（盲文图表、盒子网格、连主题格式都兼容），但只盯网络、磁盘 I/O 和 LAN——
而且盯得更深: 跨重启存活的每进程会话总量、TCP 和 UDP 的逐连接字节、带
流量的 LAN 邻居、可事后分析的无头采集。

作者自己每天 btop 和 ltop 并排开——btop 看系统，ltop 看流量——也推荐
这么用。你现成的 btop 主题在 ltop 里直接可用。

## nethogs —— 每进程，但只有当下

nethogs 打一份每进程 bytes-per-second 列表（大部分场景要 root），两次
刷新之间什么都记不住。ltop 记会话账本: 退出的进程带着总量留在屏幕上，
TCP/UDP 经 eBPF 精确归属，还有逐连接行、磁盘 I/O 和 LAN 维度。如果你只要
一份实时列表而且有 root，nethogs 更小; 其余都是 ltop 的地盘。

## iftop —— 每地址对，单接口

iftop 显示一块接口上地址对之间的带宽。ltop 的 CONNS 盒覆盖同样的视图，
外加每连接总量与速率、属主进程，以及"LAN 邻居 ↔ 连接"的联动。iftop 剩下
的优势: 预装的地方更多。

## shell 管道（ss / lsof / arp / df）

对脚本和 agent 来说这才是要紧的对比: 五种输出格式要解析、一半答案要
root、逐 socket 的 UDP 字节哪里都没有、上小时发生了什么完全无记忆。
`ltop --json` 一份 schema 稳定的快照答完（过滤后约 1.7k token），
`watch` + `report` 把"刚才发生了什么"变成两条命令加精确数字——见
[AI 代理](ai.md)。
