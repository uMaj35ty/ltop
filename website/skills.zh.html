ltop skills——教会你的 agent 观察系统

一个 markdown 文件，让编程 agent 不再刮 shell 输出，而是直接问 ltop。

skill 随仓库发布：docs/skills/ltop-observe/SKILL.md——命令、 schema 语义、平台陷阱、诊断配方都在里面。除 ltop 本体外零依赖。

安装

任何从目录加载 skill 的 agent 都能用。以 Claude Code 为例； 其他 agent 把文件夹放进它读 skill 的位置即可。

1

机器上先有 ltop

skill 驱动的是 CLI——先装 ltop（渠道）。 eBPF 助手可选；没有它 UDP 数字会降级，skill 里写明了这一点。

$ brew install uMaj35ty/ltop/ltop
2

把 skill 拷到位

一个文件一个目录——Claude Code 及兼容布局：

$ git clone --depth 1 \
    https://github.com/uMaj35ty/ltop /tmp/ltop
$ mkdir -p ~/.claude/skills
$ cp -r /tmp/ltop/docs/skills/ltop-observe \
    ~/.claude/skills/
3

自然语言直接问

"网速怎么变慢了？"——"盯着 chrome 10 分钟然后汇报流量。"skill 的 frontmatter 会被这类任务触发；agent 跑对命令、读回结构化 JSON。

$ ltop watch --duration 10m --proc chrome
$ ltop report <file> --json

skill 教了什么

agent 从"猜"到"读结构化输出"所需的全部——完整内容就是 SKILL.md 本身。

▣命令面

命令agent 拿到什么
ltop --jsonschema-v1 快照，五个域全带速率（约 1.2 秒：连采两轮）
ltop --schema随版本更新的字段参考——永不与二进制漂移
ltop watch无头 JSONL 采集：--duration / --stop 哨兵 / --proc 聚焦，崩溃安全，免 root
ltop report窗口总和、峰值、活跃时长——人读表格或 ~2 KB JSON（比轮询省 ~97% token）
jqwatch/monlog 文件就是普通 JSONL——任意切片一条过滤器的事

◉诊断配方

网速慢 → 按速率排接口、查链路状态、再看忙网卡上的头部连接。磁盘忙 → 设备吞吐对容量，再找每进程写盘者。LAN 清点 → 邻居带网关标记和 mDNS 名。时间窗任务 → watch + report，绝不轮询。

⌦防误读的语义

meta.udp_helper 标明 UDP 计费是否完整； conns[].process: null 是其他用户的 socket，不是"没有属主"； 进程总量是载荷字节、网卡总量含包头——差 10–40% 是设计使然；macOS 的 MAC 是系统脱敏，不是 ltop 藏的。
